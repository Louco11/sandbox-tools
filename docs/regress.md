# Регресс песочницы: чек-лист для агента

Проверка всего, что песочница обещает. Проходится целиком перед тем, как браться за следующий шаг плана, и после
любой правки каркаса. Пишется для агента, но любой пункт человек может повторить руками.

**Как проходить.** По порядку, сверху вниз: каждый следующий раздел опирается на предыдущий. Для каждого пункта
указано, что сделать и что должно получиться. Расхождение — не «поправлю по-тихому», а запись в `docs/roadmap.md`,
раздел 0: что делали, что ожидали, что увидели.

**Что нужно под рукой.**

```bash
make up            # стенд целиком; если уже поднят — docker compose ps без падений
make env           # секреты на месте (идемпотентно)
```

Люди стенда: ваш логин (`GITEA_HUMAN_USER`, он же администратор песочницы) и демо-люди `anna.smirnova`,
`igor.kozlov`, `maria.volkova` с паролем `KEYCLOAK_DEMO_PASSWORD` из `.env`. Ваш пароль — `KEYCLOAK_HUMAN_PASSWORD`,
при первом входе IdP попросит его сменить.

Личность для проверок без браузера подписывается внутри стенда — наружу этого нет:

```bash
docker compose exec -T identity node infra/identity/src/mint.ts <логин> <инстанс|portal|sandbox-session> 5m web
```

## 1. Контракт допуска и сборка

- [ ] `make check` — зелёный: манифесты всех тулов проходят реестр, типы сходятся.
- [ ] Сломать манифест тула (источник, которого нет в реестре) → `make check` падает и объясняет, почему источник
      недоступен и кто может его добавить. Вернуть как было.
- [ ] `node infra/demo/sandbox-call.ts validate_manifest '{"name":"manager-board"}'` — тот же ответ, что у CI.
- [ ] `node infra/demo/sandbox-call.ts list_sources '{}'` — видны все источники реестра с наборами и правами записи.

## 2. Гейтвей: скоуп, запись, аудит

- [ ] `make demo-gateway` — проходит целиком. Ключевое: чужой источник → 403, инъекция в имя поля → 400, запись без
      права → 403, без личности → 401, агент без согласия человека → 400, человек из интерфейса → 200.
- [ ] Последний раздел демо (аудит) показывает и разрешённые вызовы, и отказы, с причинами.
- [ ] Гейтвей на чужом токене: `curl -s -o /dev/null -w '%{http_code}' localhost:18080/v1/admin/tools` → 401.

## 3. Коннекторы источников

- [ ] `make demo-connector` — все проверки ✓: новый источник без правки гейтвея, запись с подтверждением, отказ без
      согласия, сетевая изоляция, реестр перечитан без перезапуска.
- [ ] `make validate-connector NAME=suppliers` — зелёный, без предупреждений о записях без сценария.
- [ ] `/v1/registry` отдаёт состав источников и не отдаёт адреса и токены коннекторов.

## 4. Личность: человек и агент

- [ ] `make demo-identity` — проходит целиком: без входа 302/401, подсунутый заголовок личности вырезан, чужой `aud`

- [ ] Браузером: открыть `http://tools.localhost:18000` в приватном окне → редирект на IdP; войти демо-человеком →
      вернулись на главную под ним.
- [ ] `bin/sandbox-mcp login` — открывает браузер, после подтверждения печатает логин и префикс ключа.
- [ ] После входа: `bin/sandbox-mcp tool manager-board` поднимается без браузера (ключ из Keychain).
- [ ] Кабинет `/me`: ключ виден, «последний раз» обновляется после вызова; «Перевыпустить» показывает новый ключ

- [ ] Каталог под посторонним не показывает чужие тулы и честно пишет, сколько скрыто.

## 10. Метрики и жизненный цикл

- [ ] `/metrics`: цифры совпадают со здравым смыслом (число тулов, владельцев, активность), демо-тулы в них не лезут.
- [ ] `/events`: фильтры (период, тул, человек, источник, канал, только отказы, без служебных) сужают срез, сортировка
      по заголовку работает, срез открывается по ссылке в другом окне и показывает то же самое.
- [ ] `/tools/<тул>/activity`: сводка «кто пользовался» и журнал — только по этому тулу; на карточке тула те же
      последние пять событий и итог за 30 дней.
- [ ] Постороннему `/events` и `/tools/<чужой тул>/activity` показывают пустой срез, а не чужие события.
- [ ] `make tools` — сроки, предел автопродления, последний заход человека.
- [ ] `make extend TOOL=… DAYS=…` продлевает; `make revoke TOOL=…` отзывает, и уборщик удаляет контейнер за ≤ 30 с.
- [ ] Отозванный тул не допускается обратно, пока его строку не уберёт уборка истории.

## 11. Выкатка, превью, защита main

- [ ] Пуш ветки с правкой тула → CI зелёный → превью `<тул>--<ветка>` поднято и открывается владельцем.
- [ ] Прямой пуш в `main` отклоняется (в том числе под администратором из `.env`).
- [ ] PR с зелёной выкаткой → одобряющим приходит уведомление; после мержа прод обновляется сам.
- [ ] Ветку удалили → превью отозвано, контейнер убран.
- [ ] Логи выкатки: `http://deploy.tools.localhost:18000/deploys/<коммит>` открывается вошедшему, `get_logs` — агенту.
